# Controller decision: CGX-PAYLOAD-COMMISSIONING-V1

The legacy controller is not a configurable payload inverse-dynamics controller. `src/cgx/env/system.py` computes `q_command = q_measured + .20*(q_reference-q_measured) - .02*dq_measured`. The pinned Menagerie model then supplies a position actuator inner loop, with arm gains 4500/3500/2000 and affine position/velocity bias. The legacy controller has no payload update interface and reads no plant `qfrc_bias`, mass matrix, or true acceleration.

For this experiment, `payload_change_v1/physics.py` introduces one common fixed torque controller. All four methods and both references use it. Its torque request is inverse dynamics of the public configured model at delivered measured q/dq and reference acceleration, plus fixed PD feedback. The controller never receives the unknown plant model. The controller and estimator use independent MjData objects and immutable public model specifications. Plant models have a separate compilation key and retain physical contacts. No runtime mass/inertia arrays are edited. Reconfiguring the controller recompiles a public specification and does not touch the plant.

The new arm actuators have unit transmission gear, direct force gain 1, and zero affine bias. Their force limits are inherited from the pinned original XML/defaults: 87 Nm for joints 1–4 and 12 Nm for joints 5–7. These are model limits, not a claim about every physical Panda system. A common 1000 Nm/s command slew limit is a simulation setting. No automatic gravcomp is enabled.

The initial gain candidate reused the old outer-servo effective stiffness: Kp=[900,900,700,700,400,400,400], with explicit torque-loop Kd=[50,50,40,40,20,20,20]. A one-case profile passed smooth motions, but complete source collection exposed 167 L0 hard aborts, including correct-configuration cases. These runs remain an archived engineering attempt, not final scientific source data. Raw traces show feedback overshoot under the unchanged 1000 Nm/s rate limiter: one correct-configuration case requested -307 Nm while the previously positive applied torque was still +29.9 Nm, accelerating joint 1 beyond the 6 rad/s hard limit. The nominal HOME linearized closed-loop spectral radius was 0.911, so the observed problem was nonlinear rate-limiter overshoot, not evidence of simple local linear instability.

Three fixed lower-bandwidth candidates were registered and tested on 24 nominal true-configuration source cases (G0/G1, two per family), without examining stale-setting success to choose gains. High stiffness with reduced damping produced 22/24 hard aborts; moderate stiffness/damping produced 1/24; the lower candidate produced 0/24. All three passed 24/24 smooth work trajectories. The lower candidate was then checked on all 192 source payloads with correct true configurations: 0/192 L0 hard aborts, 59/192 L0 full acceptance, and 192/192 smooth work acceptance. L0 failures from saturation or trajectory error remain failures; its reference and every physical limit are unchanged.

The final frozen controller is `payload-id-pd-v2-source-qualified`, Kp=[200,200,150,150,80,80,60] Nm/rad and Kd=[10,10,8,8,5,5,4] Nm*s/rad. The full candidate records, raw failures, and qualification counts are retained under `source_validation/gain_qualification` and `checks/source_controller_qualification.json`. Final settings are in `configs/controller.json`.

The known gripper is rigidly fixed at its original open position of 0.04 m per finger. Original finger geometry and mass are retained exactly once. The finger tendons, equality, and finger actuator are removed from the new compiled model, giving a fixed known tool and seven controlled arm degrees of freedom. This is a declared new-task model change; it is not described as numerically identical to the old software-fault experiment. The hand frame is the declared payload mount frame; inertia_com is about the payload COM and expressed in that frame. The payload is rigidly attached without a free joint. Its collision envelope retains fixed exterior dimensions, while private internally generated mass distributions supply physically consistent mass, COM, and inertia. Legal attachment contacts are excluded; other robot/environment contacts remain enabled.

The original L0 reference function is imported directly and verified at all 5000 physics timestamps. Its 100 ms transitions are preserved. On the initial-gain nominal source profile L0 completed 10 s with 1.78 mm RMS tracking error, but failed the 1% saturation-time criterion (1.5%). This is retained as a legacy-reference constraint failure, not repaired by softening L0. All smooth source work/library motions passed. A separate early diagnostic sequence incorrectly applied L0 after a work trajectory, far from its declared initial home, and triggered a velocity abort. Its raw failure records and physics charge remain under `source_validation/controller_initial`; formal L0 always begins from the defined initial home distribution.

The plant advances at 500 Hz; sensing, software routing, and command updates run at 100 Hz. Every healthy graph Module/Packet operation executes, including adapters, cache, queue, sensor, controller, and actuator. All software ports are recorded. Command packets now contain Nm rather than position targets; graph nominal adapter transforms still encode/decode those numeric commands. Estimation sees only the public sensor projection, not the plant instance.

Torque measurement is `qfrc_actuator` sampled at the same pre-command instant as q/dq, plus a persistent 0.02 Nm standard-deviation per-joint bias and stationary AR(1) noise (0.05 Nm, rho=0.6). It is a simulated joint execution torque measurement with unit gear and joint-coordinate sign, not an exact recreation of Panda link-side torque sensing. The newly requested/applied command describes the following 10 ms interval. q/dq noise is 1e-4 rad/1e-3 rad/s. The persistent bias and AR state continue across action blocks. No true acceleration or true-load inverse-dynamics residual is exposed.

Public inverse dynamics writes its supplied acceleration into its own data.qacc before `mj_inverse`; qfrc_inverse includes known armature and subtracts passive forces. Thus known damping is compensated once. Contacts/constraints are disabled only for the public inverse-dynamics model; actual plant constraints remain enabled. Acceptance is computed both from public noisy-encoder FK at 100 Hz and separately from evaluator physical state at 500 Hz. No inverse-dynamics predictor replaces actual verification or private audits.

Qualification: `checks/physical_integrity.json` records 16 passed physical integrity checks; `checks/physical_payload_effects.json` records paired source evidence that changing actual payload at fixed settings changes physical q and torque, and changing settings at fixed payload changes requests and tracking. `resources/profile20.json` contains every profile block and compressed record sizes. Full validation-history branching uses evaluator-only `clone()`, which copies MuJoCo integration state, RNG, bias, AR state, command and actual routing state. Two independently charged source continuations agree bit for bit in both public and private arrays.

Installed MuJoCo is 4.0.1; no package was upgraded. Version-specific 4.0.1 documentation URLs were unavailable through the web tool, so the stable official API text was cross-checked against the installed binding/docstrings. It states that qacc must be set before mj_inverse and its output is qfrc_inverse. All models are compiled from immutable XML, avoiding ambiguity about runtime model edits.

Before formal source collection, a strict-boundary review changed the initial gravity-hold request to use the public HOME reference, rather than the exact perturbed initial plant q. The first and every subsequent 100 Hz feedback command uses noisy encoder readings. This avoids even a one-time exact-state initialization query and consumes no extra sensor RNG draws. The original 20-block performance profile predates this one-line correction and remains labeled engineering profiling. Four additional source runs (nominal plus the three paired payload/configuration conditions) revalidate the final initialization in `checks/initial_hold_revalidation.json`; all formal data use this final code.
